Layers, last one wins: 1. built-in defaults (below) 2. the data file named by `from` 3. the page's `heroslider` front matter: a string (the data file name) or a map with the same keys as the data file, `from` included. It applies only to the slider it names: an hw call with a different `from` skips it 4. hw props passed to this partial Data file keys (all optional): includedata data file the slides come from; omit and they are in this file slides list key inside that file (default: its basename, then "slides") map {hwName: dataKey} per slide, e.g. {header: name, src: logo}; an omitted hw name reads the key of the same name header the carousel's aria-label (not a heading: the hero owns the h1) srcOn left | right | top | bottom — image beside, over or under text srcWidth 0.0-1.0, the image's share of a left/right slide process Hugo process string for raster slides interval seconds between auto-advances; 0 = manual only display_order default | reversed | random. default is by `weight`, lowest first, when the list has one, else the data file's order; reversed is that backwards. random shuffles here, once per build, AND tool/heroslider's script reshuffles on every page load; the build shuffle is what a visitor without JS sees. Applied before skip/count, so random with a count shows a different subset per build. count, skip limit the list / skip from its start geometry CSS values: width, height, align (left|center|right), and ONE of top | bottom (the offset from that edge of the hero). A layer setting one replaces the other from the layers below it; setting both in one layer is an error. List handling: items with `active: false` are dropped, then display_order is applied, then skip and count. Caveat for hw props: the hw shortcode always sends count=1 and srcOn="left", so those two values cannot be told from "not set" and are ignored as props. Front matter keys arrive lowercased from Hugo; every layer is lowercased here so `srcOn` and `srcon` are the same key. DO NOT call partial "tk/dbg-template" - it prevents return from working. returns (dict "slides" []dict — src alt header text link srcOn srcWidth process, per slide "edge" string — "top" or "bottom"
